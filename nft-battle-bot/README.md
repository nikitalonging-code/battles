# NFT Battle Bot

Мини-апп для батлов на NFT-подарки Telegram. Кубик решает, кто забирает подарки соперников.

## Как это работает

1. Игрок подключает бота как **Business-бота** в Telegram: `Настройки → Telegram Business → Чат-боты`,
   выбирает бота и включает права **«Просмотр подарков и звёзд»** и **«Передача и апгрейд подарков»**.
   Подарок физически никуда не отправляется — он остаётся у владельца, просто у бота появляется
   разрешение прочитать список подарков и передать их от лица владельца.
2. В мини-аппе игрок создаёт битву и выбирает NFT-подарок из своих (`GET /api/gifts`).
3. Другие игроки вступают, тоже ставя по подарку, пока не заполнятся слоты (по умолчанию 3).
4. Когда слоты заполнены, бот бросает кубик (`sendDice`) за каждого участника в канал результатов,
   у кого больше очков — тот победитель (при ничьей — перебрасывают только лидеров).
5. Бот переводит подарки проигравших победителю через `transferGift`.
6. Кнопка «Проверить» в карточке битвы ведёт на сообщение в канале с результатами.

## Установка

```bash
cd nft-battle-bot
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN, RESULTS_CHANNEL, WEBAPP_URL
python main.py
```

`main.py` поднимает одновременно long-polling бота и FastAPI (порт 8000, отдаёт и API, и статику мини-аппа).
Для мини-аппа в проде нужен HTTPS-домен (Telegram не откроет `http://` WebApp) — задайте его в `WEBAPP_URL`
и прокиньте туда порт 8000 через nginx/Caddy или используйте туннель (например Cloudflare Tunnel) на этапе теста.

Канал результатов (`RESULTS_CHANNEL`) должен быть публичным (с юзернеймом), чтобы кнопка «Проверить» могла
сослаться на конкретное сообщение по ссылке `t.me/<channel>/<message_id>`. Бот должен быть админом канала
с правом писать сообщения.

## Деплой на Render

1. Залейте проект в GitHub-репозиторий (Render деплоит из репо).
2. На [render.com](https://render.com) → **New** → **Web Service**, подключите репозиторий.
   Render сам подхватит `render.yaml` (Blueprint) — либо настройте вручную:
   - **Build command:** `pip install -r requirements.txt`
   - **Start command:** `python main.py`
3. В **Environment** добавьте переменные: `BOT_TOKEN`, `RESULTS_CHANNEL`, `DATABASE_URL`, `ADMIN_IDS`.
4. `WEBAPP_URL` заполните **после** первого деплоя — Render выдаст домен вида
   `https://nft-battle-bot.onrender.com`, его и укажите. Затем нажмите **Manual Deploy** ещё раз,
   чтобы бот перезапустился с правильным URL, и пропишите этот же адрес в BotFather (Menu Button).
5. Тот же домен нужно указать как `RESULTS_CHANNEL`-независимо — он используется и для API, и для
   раздачи мини-аппа (`app.mount("/", StaticFiles(...))` в `app/api.py`), отдельно ничего разворачивать не надо.

**Важные ограничения бесплатного плана Render:**
- **Free web service засыпает** после ~15 минут без HTTP-запросов и убивает процесс — вместе с ним
  умирает `long polling` бота (`start_polling`), то есть бот перестаёт отвечать, пока кто-то не откроет
  мини-апп и не "разбудит" сервис (с задержкой в десятки секунд). Для стабильной работы бота нужен минимум
  план **Starter** ($7/мес), на нём процесс не засыпает.
- **Диск эфемерный на free-плане** — файл SQLite (`battles.db`) обнулится при каждом передеплое/рестарте.
  В `render.yaml` уже прописан persistent disk (`/data`), но он тоже доступен только начиная со Starter.
  Если нужно остаться на бесплатном плане — переключитесь на бесплатный Render Postgres вместо SQLite,
  он переживает рестарты.
- Если хотите не зависеть от "просыпания" по HTTP-запросу — могу переключить бота с `long polling` на
  `webhook`-режим (Telegram сам стучится в ваш сервис), это надёжнее именно на PaaS вроде Render. Скажите,
  если нужно — перепишу `bot.py`/`main.py` под вебхук.

## Что уже сделано

- Модели битв/участников/пользователей (`app/models.py`)
- Создание и вступление в битву, розыгрыш кубиками, авто-передача подарков (`app/battles.py`)
- Чтение и перевод NFT-подарков через Business API (`app/gifts.py`)
- Валидация `initData` мини-аппа (`app/telegram_auth.py`)
- REST API для мини-аппа (`app/api.py`)
- Мини-апп на чистом HTML/CSS/JS в стиле скриншота (`webapp/`)
- Нижняя навигация (Слоты/Джекпот/Инвентарь/Профиль) — кнопки-заглушки, логику добавим отдельно под каждую

## Что стоит доделать перед боевым запуском

- **Оценка стоимости подарка в TON.** Bot API не отдаёт текущую рыночную цену NFT — только
  `last_resale_amount`, если подарок вообще перепродавался. Для честного отображения "цены битвы"
  потребуется парсер маркетплейса (Portals/Tonnel/MRKT и т.п.) или ручной ввод оценки при ставке.
- **Идемпотентность и гонки** при одновременном вступлении нескольких игроков в последний слот —
  сейчас есть базовая проверка в `join_battle`, но под нагрузкой стоит добавить блокировку на уровне БД
  (`SELECT ... FOR UPDATE` при переходе на Postgres).
- **Обработка сбоя `transferGift`** (например, если владелец успел передать/продать подарок в другом месте
  между стейком и розыгрышем) — сейчас ошибка просто логируется в сообщение канала, нужен полноценный
  сценарий возврата/арбитража.
- **Отмена битвы**, если она долго висит без соперников (сейчас статус `CANCELLED` заведён в модели,
  но обработчика ещё нет).
- Кнопки «Слоты», «Джекпот», «Инвентарь», «Профиль» — заглушки, как и просили, логику добавим позже.

## Важное юридическое замечание

Это по сути платформа для ставок на активы с реальной рыночной стоимостью (NFT-подарки торгуются за TON).
В части юрисдикций такая механика подпадает под регулирование азартных игр, а сам Telegram может расценить
подобный мини-апп как нарушение своих правил использования ботов/платформы. Соответствие законам вашей
страны и правилам Telegram — зона ответственности того, кто запускает и эксплуатирует бота.
